# AGENTS.md

WhatsApp bot (Node.js/Express, ESM) with two coexisting flows: (1) laptop queries from `Laptops.xlsx` via exceljs (authorized users only, opt-in via `hola bot`), and (2) a public school-supplies sales flow ("útiles escolares") from `UtilesEscolares.xlsx` that anyone can use. User-facing replies and console logs are in Spanish.

## AI (optional) — Google Gemini free tier
The útiles flow has an **optional AI mode**: if `GEMINI_API_KEY` is set (`lib/ai.js`, no new deps, uses global `fetch`), the greeting's option **1** (and any free text / photo / document from the saludo) enters state `IA_CHAT` — a free-form dialogue driven by `gemini-3.1-flash-lite` (`GEMINI_MODEL` env). Model output is **structured JSON** (`askGemini` in `lib/ai.js`, `responseMimeType: application/json` + `responseSchema`): `reply`, `carrito[{producto,cantidad}]`, `entrega{direccion,diaHora,nombre,genero,domicilio}`, `pedido_finalizado`, `despedirse`, `enviar_catalogo`. **The bot never trusts Gemini for prices**: every `carrito` entry is re-validated against the catalog via `findItems` before entering `seleccion`; the final quote image is always built by `buildPriceImage` from catalog data. When `pedido_finalizado` is true the bot renders the final image **before** Gemini's confirmation reply, then sends a short payment text with the exact 50% amount (`PAYMENT_IA`, e.g. "transfiere el anticipo del 50%: $12.50") and moves to `ESPERA_COMPROBANTE`. In `ESPERA_COMPROBANTE` the receipt is **verified with Gemini vision** (`askGeminiReceipt` in `lib/ai.js`): it first checks the image is really a payment comprobante (`es_comprobante`), extracts monto/titular/fecha and checks that the amount is ≥ the 50% anticipo, the holder is "Evelyn Lizeth Zambrano" and the comprobante date is **today** (America/Guayaquil) → if OK replies `COMPROBANTE_OK_IA` (thanks + closes the session); if not, replies a kind, **varied** message (`COMPROBANTE_MAL_VARIANTS`, cycled by `session.receiptAttempts`, third attempt offers an asesor) with the motivo and stays waiting. Re-sending the **same image** gets `COMPROBANTE_MISMA_IMAGEN` instead of a repeated review. If AI is off or fails, it falls back to the manual `COMPROBANTE_MANUAL` path (operator logs the expected 50% and today's date). Menu options 2/3 (Evelyn / chatbot para tu negocio), the laptop flow, and the entire rule state machine are untouched when AI is on; **without a key the bot behaves exactly as before** (all tests pass). On API errors/quota (429) `askGemini` returns `null` → reply `AI_FALLBACK` and the session stays in `IA_CHAT` (never breaks). Photos sent in `IA_CHAT` are downloaded (`server.js normalizeInbound`, only when `isAiEnabled()`) and sent to Gemini inline as base64 (free vision). Conversation history lives in `session.iaHistory` (last ~24 turns).

> Model note: Google retired the 2.x models for new API keys (404). Use a current free model — `gemini-3.1-flash-lite` (default), `gemini-3.5-flash`, or `gemini-3.6-flash` — via `GEMINI_MODEL`. The `generateContent` endpoint is still supported (legacy); the newer Interactions API is not used here.

## Commands
- `npm start` runs the server.
- `npm test` runs `node --test test-usability.mjs` (unit/usability tests, read-only). There is no lint/typecheck setup.

## Excel quirks (easy to miss)
- Sheets are named `Laptos` (typo — keep it) and `Autorizacion`. Don't rename them.
- `Laptos` header row is row **4**; data starts at row 5. Columns map to `FIELD_ALIASES` in `lib/excel.js:6`.
- `Autorizacion` header row 1 (`Nombre`, `Celular`); rows 2+ are the only authorized numbers. Matching compares the last 9 digits (min 7) of the sender's number.
- `UtilesEscolares.xlsx` (slim copy, no photos): sheet `Hoja1`, header row **1** = `Producto | Descripcion | Precio de venta al publico ` (trailing space + NBSP possible — `normalize()` handles it). Rows 2+ are the 59 products (the catalog grows as rows are added). The price header contains a non-breaking space and trailing space; `normalize()` in `lib/excel.js:26` (lowercase + strip accents + trim + NBSP→space) is what makes the alias `'precio de venta al publico'` match in `lib/utiles.js`.
- **Product photos**: drop images into `imagenes/` named `<Número de producto>.<ext>` (e.g. `1.jpg`, `12.png`; `.jpg/.jpeg/.png/.webp`). `findProductImage()` in `lib/utiles.js` resolves them (dir overridable via `UTILES_IMAGES_DIR` env). When the AI chat asks for a photo of a product that has an image, Gemini marks `enviar_foto` with the product number and the bot sends that file via `sendProductPhoto()` (no photo → message "no tengo una foto disponible" + catalog link). The build of the AI system prompt lists exactly which products have photos, so Gemini never claims a photo exists that isn't in the folder.
- All matching/text goes through `normalize()` in `lib/excel.js:26` (lowercase + strip accents). `normalize()` also converts `\u00a0`→space and trims.

## Gotchas
- `server.js` caches both workbooks for the process lifetime (cache key `EXCEL_PATH|UTILES_PATH`). Edits to either `.xlsx` require restarting the server; in production (Render) that means pushing the updated file to GitHub `main` → auto-redeploy. The YCloud webhook URL never changes. The útiles store loads the catalog **lazily** (`ensureProducts()` in `lib/store.js`): the greeting and option 2/`no`/`asesor` never fetch it — it's loaded into memory on the first action that needs it (option 1, option 3, a product query or a confirmed document) and stays cached for the process.
- **Production runs on Render** (`pc-venta-ia.onrender.com`). Env vars live in the Render dashboard (`YCLOUD_API_KEY`, `YCLOUD_PHONE`, `YCLOUD_WEBHOOK_SECRET`, `GEMINI_API_KEY`), not in `.env`. The repo is private; `.env` and `node_modules` must never be committed.
- Without `PHONE_NUMBER_ID`/`ACCESS_TOKEN` in `.env`, replies are only logged to console (dev mode). `.env` is gitignored; copy `.env.example`. Signature verification (Meta `x-hub-signature-256` and YCloud `ycloud-signature`) is skipped only when the corresponding secret is empty; when a secret is set, a request missing its signature header is rejected with `401`.
- **Webhook routing** (`server.js`, in order): (1) authorized + active laptop session + text → laptop flow (`generateReply`, `chao bot` deactivates); (2) authorized + active laptop session + media → ignored; (3) authorized without session + `hola bot` → activate laptop session + `HELP`; (4) non-authorized + `hola bot` → silent (log only, no reply — keeps WhatsApp Business App coexistence working); (5) **everything else → útiles flow** (`utilesStore.handleMessage`), including all non-authorized messages, non-activation messages from authorized users, and incoming media.
- **Per-sender serialization**: `runSerialized(from, fn)` in `server.js` queues message processing per `from` so the in-memory state machines (laptop `activeSessions` and each útiles session) never race when a user sends several messages quickly. `res.sendStatus(200)` is sent before processing, so YCloud/Meta won't retry.
- **Laptop session activation** (`lib/search.js`): `hola bot` (`isActivationMessage`, substring on normalized text) activates; `chao bot` (`isDeactivationMessage`) deactivates. The útiles flow is always on for everyone else.
- Reply routing in `lib/search.js:73` is keyword-based and checked in order: both `disponible`+`arrendad` → `disponible` → `arrendad` → `cuant|total|inventario` → serial token match → `codigo <n>` (exact `l.codigo` match, handles 1+ digit codes) → "sin serial" (serial + `sin|no|falt|vacio|registr`, lists laptops with empty `serial`) → token scoring (greetings-only messages return the help text). New intents must slot into this order.
- **Útiles flow** (`lib/store.js`): a state machine per `from` with states `SALUDO → (IA_CHAT | CHATBOT | ESPERA_LISTA) | CHATBOT → CHATBOT_CONFIRMA → CHATBOT_EDITAR | SELECCION → CANTIDAD → AGREGADO → (SUGERENCIA → CONFIRMA_SUGERENCIA → MODELO_MOCHILA) → CONFIRMA_COTIZACION → GENERO | CONFIRMA_ARCHIVO → PREGUNTA_PRODUCTO → PREGUNTA_DISPONIBLE → ENTREGA → UBICACION → DIA_HORA → NOMBRE_ENTREGA → CONFIRMA_PEDIDO → ESPERA_COMPROBANTE | MODIFICAR → (AGREGADO | RETIRAR)` (plus `DESACTIVADO`, which keeps the session but makes the bot silent). First message of a session always gets the greeting; it shows options `1` (cotización), `2`/`no` → Evelyn, `3` (chatbot para tu negocio) — **no catalog option in the greeting** (the catalog is shown on request by word via `isCatalogRequest`, e.g. "catálogo"/"qué tienes", or after option 1 via `PREGUNTA_DISPONIBLE`). `2`/`no` → reply "Ok, de aquí en adelante Evelyn chateará contigo." and go to `DESACTIVADO` (the bot never replies again for that `from` until the process restarts, so Evelyn continues the conversation manually from WhatsApp Business); a free-text request to talk to Evelyn (matched by `isTalkToEvelyn`, e.g. "necesito comunicarme con Evelyn", checked in `handleMessage` before any other intent/state, so it works in every state and both AI/non-AI) does the same. Option `3` (or any text with the word `chatbot`/`bot inteligente` via `isChatbotRequest`, from any state) → `CHATBOT`: an 8-question requirements form (`CHATBOT_FIELDS`: negocio, productos, canales, tareas, volumen, catálogo, integraciones/idioma, contacto) storing answers in `session.chatbotInfo`; after the last answer it sends a summary (`buildChatbotSummary`) + approval ask → `CHATBOT_CONFIRMA`; `sí` logs the requirements for the operator and replies that an asesor will contact the client personally (closes the session); any other reply → `CHATBOT_EDITAR` (numbered field list → pick a number → enter the new value → updated summary → back to `CHATBOT_CONFIRMA`; "listo" returns to the summary). Media in the chatbot states replies `CHATBOT_SOLO_TEXTO` and stays in state. Multi-line text lists are matched directly; **PDF/Excel documents first ask `CONFIRMA_ARCHIVO` ("Recibí tu archivo. ¿Genero la cotización con esa lista?")** (buffer kept in `session.pendingFile`), and on `sí` set `session.busy = true` while parsing (`parseFile`, try/catch → `FILE_UNREADABLE` on failure) + building the image, cleared in `finally` (`isBusy(from)` is exposed for the webhook, which replies `ESPERA_GENERANDO` immediately to any message arriving while busy; `completar el pedido`/`detener` in `CONFIRMA_COTIZACION` jumps straight to `MODIFICAR`). `CONFIRMA_COTIZACION` asks "¿Estás de acuerdo con la cotización? Si deseas ajustar algo, dime qué producto agregar o quitar."; `no`/`modificar`/`2` (or any other reply) → `AGREGADO` (modify); `1`/`sí`/`de acuerdo` → `GENERO` ("¿Tu lista de útiles es para niña o para niño? Dime cuál.", stores `session.genero` rendered as "Para: X" in the final cotización image, re-asks on invalid) → `ENTREGA`. On `no` → `PREGUNTA_PRODUCTO` ("¿Deseas preguntar por un producto específico?"), and its `no` → `PREGUNTA_DISPONIBLE` ("¿Deseas ver lo que tengo disponible?") → `sí` sends the full catalog (producto, descripción y precio, via `catalogoText()`) and goes to `ESPERA_LISTA`; its `no` → farewell + closes. Asking "qué tienes"/"catálogo"/"qué hay" (matched by `isCatalogRequest`, checked before the payment/photo intents, any state except `ESPERA_COMPROBANTE`) sends the same catalog text and keeps the current state. When offering mochilas/cartucheras/loncheras (`SUGERENCIA`/`CONFIRMA_SUGERENCIA`) the replies append the WhatsApp catalog link `https://wa.me/c/593987695938`. After `UBICACION` (dirección) and `DIA_HORA` (día/horario), `NOMBRE_ENTREGA` asks "¿A nombre de quién realizamos la entrega?" and stores `session.nombreEntrega`, which is rendered as "A nombre de: X" in the final cotización image. Lines are classified by `matchListLines()` (`lib/utiles.js`) into 4 buckets (a line that is only a quantity continuation — `unidades)`, `pcs)`, `)` — following a line ending in a digit is merged into it first, so `1 caja de pinturas triangulares gigantes 12` + `unidades)` become one item), and a line **starting with `para`** is merged into the previous line (continuation, so `cartuchera` + `para niña` → one priced item); an orphan `para` fragment (no previous line) is dropped in `matchListLines` and in `handleEsperaLista` a lone message starting with `para` → `PIDE_LISTA`, checked in order: **header** (text with `grado|curso|paralelo|escuela|colegio|unidad educativa` only — no "lista de útiles"/"nombre del estudiante"/"año lectivo" — → rendered at the top of the image, also stored in `session.headers` for the preliminary/final images), **footer** (`fecha|entrega|firma|docente|profesor|maestro|nota|observacion|adicional|por favor|agradec|gracias|atentamente|importante|recordar|presentar|presente lista|inicio de clases|debe|deber` → dropped, never shown), **omit** (`libro|libros|novela|uniforme|dirección|domicilio|calle|avenida|cdla|urbanización|ciudadela|referencia|teléfono|celular|correo|email|whatsapp` → dropped, never shown), and **product** (verificación de pertenencia: a line is quoted only if it belongs to útiles escolares/limpieza. `findItems` matches per-word with **IDF weighting** (rare tokens like `triangular` outrank generic ones like `caja`, so `caja de pinturas triangulares` → *Caja de Esfero Triangular Bester* (a real catalog product) and NOT *Caja de 12 lápices*; `pinturas jumbo` → *Pintura Jumbo Triangulare*; `caja de 12 lapices` still → *Caja de 12 lápices*) and singular/plural-aware (`pinturas`↔`pintura`, `triangulares`↔`triangulare`); it requires ≥1 token in the product **name** (description-only matches are discarded → `regla de 30 cm` picks *Regla Bester de 30 cm*, not *Juego Geométrico*; `escuadra`→no match). Name match → priced row showing the **client's original line text** (the catalog name is kept internally as `producto` for the operator, not displayed); no name match but a `UTILES_ITEM_RE`/`LIMPIEZA_ITEM_RE` keyword (`cuaderno, lapiz, goma, regla, tijera, mochila, cartuchera, escoba, jabon, cloro, cepillo dental, papel higienico, archivador, mandil, rompecabezas, vaso, pelota...`) → row "No disponible" (belongs but not in catalog, original text shown); neither → the line is **dropped** (never quoted, e.g. `xyzfoo`). Only priced items enter `seleccion`). Item rows keep the **document line order** (no reordering). Items are matched against `Producto`+`Descripcion` via `findItems()` (`lib/utiles.js`, token scoring, top 5, **min token length 3**, measure words `unidad|unidades|unids|pcs` are stopwords so a stray `unidades)` is never priced) → they populate the session's `seleccion` map and a preliminary PNG price image is built with `buildPriceImage()` (sharp) → asks "¿Es esta la cotización que deseas? 1/2". `2` → `MODIFICAR` (add or remove products). `1` → `ENTREGA` (delivery only) → `UBICACION` stores `session.direccion` → `DIA_HORA` stores `session.diaHora` → final cotización image rendered with an ENTREGA block (`buildPriceImage(rows, { entrega })`) + 3-option menu (1. Realizar el pedido / 2. Deseo modificarlo / 3. No estoy interesado). Option 1 → `ESPERA_COMPROBANTE`: instructs to transfer the 50% (non-refundable) **indicating the exact amount** + the rest on delivery and attach the receipt; **the receipt is not OCR'd — verification is manual**: any image/document while in `ESPERA_COMPROBANTE` is treated as the comprobante, logs the customer, order total and expected 50% for the operator, replies "Recibimos tu comprobante... Verificaremos que el anticipo del 50% ($X)... a nombre de Evelyn Lizeth Zambrano con fecha de hoy" and closes the session (text in that state re-asks for the receipt). Option 3 → cordial farewell and closes. A single product query shows price and asks quantity (`CANTIDAD`), stored in `seleccion`. Session fields: `direccion`, `diaHora`, `nombreEntrega`, `genero`, `sugerido` (once suggested, mochilas/cartucheras/loncheras are offered at most once per shopping round), `pendingFile` (document buffer awaiting confirmation), `busy` (generation in progress). In `ESPERA_LISTA`, messages mentioning a sent file (`pdf|archivo|documento|adjunt|envie|mande|mando|reenviar|subi|recibi|ya te`) → `ARCHIVO_NO_RECIBIDO` (stays in state); question/complaint wording (`de donde|donde|por que|porque|para que|de que|que es|como`) → re-send `PIDE_LISTA`; zero product hits → `PIDE_LISTA` (not `NO_ENCONTRADO`). `pago`/`transferencia` → payment instructions; `foto`/`imagen`/`catalogo` → "en nuestro catálogo..." (stays in state); photos are never OCR'd. Idle timers: 5 min → follow-up ("¿Sigues ahí?") only if the sale is not concluded, 14 min → "El chat se cerrará por falta de respuesta." and the session closes; if the sale already concluded (state `ESPERA_CONFIRMACION_RECIBO` or `PICKUP_AGENDA`) no idle message is sent — the session is dropped silently.
- **YCloud adapter** (`server.js`): if `YCLOUD_API_KEY` is set, text sends via `POST https://api.ycloud.com/v2/whatsapp/messages` with `X-API-Key`, body `{ from, to, type: "text", text: { body } }` (E.164 with `+`). `from` uses `YCLOUD_PHONE` or falls back to the inbound message's `to`. Images: upload `POST https://api.ycloud.com/v2/whatsapp/media/{phone}/upload` (multipart field `file`, E.164 with `+`, response `{ id }`), then send `{ type: "image", image: { id } }`. Incoming media (YCloud: `image.link`/`document.link` URLs; Meta: media ids resolved via Graph API) is downloaded by `downloadMedia()`. Incoming events are `whatsapp.inbound_message.received` under `event.whatsappInboundMessage` (`from`, `to`, `text.body`, `image`/`document`); both YCloud and Meta (`entry[].changes[]`) payloads are parsed by `toMessages()`. Signature header `YCloud-Signature` (`t=<ts>,s=<hex>` over `<ts>.<rawBody>`, HMAC-SHA256 with `YCLOUD_WEBHOOK_SECRET`) is verified when that secret is set. Otherwise the Graph API path is used (requires `PHONE_NUMBER_ID`/`ACCESS_TOKEN`).

## Layout
- `server.js` — Express server, webhook verify/signature, routing, media upload/download, Graph API/YCloud send
- `lib/excel.js` — workbook load/parse + authorization + `normalize()`
- `lib/search.js` — laptop query interpretation and reply generation
- `lib/utiles.js` — útiles catalog parse, `findItems` lookup, item/file parsing, `buildPriceImage` (sharp), `formatPrice`
- `lib/store.js` — útiles state machine, per-session `seleccion` cache, idle timers
- `lib/ai.js` — optional Gemini integration (`isAiEnabled`, `askGemini` JSON, `buildCatalogContext`)
